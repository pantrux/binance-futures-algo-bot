## Objetivo
- agregar modo live `ema_rsi_baseline` al worker
- permitir activarlo por símbolo vía `SIGNAL_STRATEGY_SYMBOLS`
- mantener `hybrid` como default sin romper el flujo actual

## Cambios principales
- se agrega `SIGNAL_STRATEGY=hybrid|ema_rsi_baseline`
- se agrega `SIGNAL_STRATEGY_SYMBOLS` con normalización y allowlist por símbolo
- `build_signal_services()` propaga `strategy_mode` y `strategy_symbols` a cada timeframe
- `HybridSignalService` soporta una rama baseline EMA/RSI sin alterar la rama `hybrid`
- se restauró explícitamente la lógica original de `side` para `hybrid`
- se limpiaron cálculos redundantes y se reforzó cobertura de tests
- `BacktestingService.CANDIDATE_PARAMETERS` se actualiza **intencionalmente** para alinear el walk-forward con la nueva estrategia `ema_rsi_baseline`

## Riesgo / impacto
- riesgo bajo en el worker live: `hybrid` sigue siendo el default y su lógica original quedó preservada
- impacto controlado en `ema_rsi_baseline`: solo aplica cuando se configura explícitamente
- impacto deliberado en backtesting: los candidatos se ajustan para reflejar la estrategia baseline; esto puede cambiar comparaciones históricas previas y se considera parte intencional del cambio

## Documentación
- configuración nueva:
  - `SIGNAL_STRATEGY=hybrid|ema_rsi_baseline`
  - `SIGNAL_STRATEGY_SYMBOLS=ETHUSDT`
- nota: `SIGNAL_STRATEGY_SYMBOLS` acepta string vacío o `[]` como allowlist vacía
